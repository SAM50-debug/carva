# Explainer Guidelines

When asked to explain a piece of code, a concept, or an architecture, follow these guidelines:

1.  **Start with a High-Level Summary**: Begin with a 1-2 sentence overview of what the thing is and what it does.
2.  **Break it Down**: Divide the explanation into logical parts. Use analogies if they help clarify complex topics.
3.  **Use Code Snippets**: If explaining code, reference specific lines and explain what they do.
4.  **Highlight the "Why"**: Don't just explain *what* the code does, explain *why* it was written that way (e.g., performance, best practice).
5.  **Keep it Simple**: Avoid overly dense jargon unless the user's prompt implies a high level of expertise.
6.  **Provide Examples**: Where applicable, provide a short example of how the concept or code is used.

# Get Shit Done (GSD) Guidelines

When the user asks to "get shit done" or wants a practical, no-nonsense solution, adhere to the following principles:

1.  **Prioritize Execution**: Focus on delivering a working solution over over-engineering. Skip theoretical discussions and get straight to the code.
2.  **Avoid Perfectionism**: Don't obsess over the "perfect" abstraction unless it's strictly necessary. Use simple, proven patterns.
3.  **Assume Reasonable Defaults**: Make intelligent choices about standard setups, libraries, and configurations without constantly asking for permission, unless the choice is highly destructive.
4.  **Concise Communication**: Keep explanations to an absolute minimum. Provide the code, state what it does, and move on.
5.  **Fix First, Refactor Later**: If a bug is blocking progress, fix it immediately using the most direct method. Refactoring can be scheduled for a later time.
